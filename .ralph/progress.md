# Progress: phase 6, a refund executes once, live (specs/features/06-refund-executes-once)

## T-001 (done)
- `@countersign/rail-paypal` gains `refundCapture({ captureId, amount, customId, requestId })` (call `refund-capture`), `getRefund(id)` (call `get-refund`), `PayPalRefund` records (status is the enum `REFUND_STATUSES`; capture ID from the `up` link, else null), `refunds` on every purchase unit, and `refundedTotal(order, captureId): number | null`.
- Gotcha: `refundedTotal` returns null (unknown) when the capture isn't on the order, a counted refund's currency differs, or an unattributable counted refund sits in a multi-capture unit. T-004 should leave the capture snapshot out on null.
- Gotcha: an order refund with an unknown status makes the whole order unreadable (`invalid_response`), which is fail closed. Fixtures: `refund-capture-completed`, `get-refund-pending`, `get-order-refunded`, `error-422-capture-fully-refunded`.

It has no request ID, so it's never retried on 5xx; a 401 still triggers the one token refresh. Fixtures: `list-disputes-page-1`/`-2`, `verify-webhook-signature-success`/`-failure`.

## T-003 (done)
- `@countersign/ledger` `ENTRY_TYPES` gains `execution.requested`, `execution.result`, `reconciliation`. `apps/gate/src/execution-log.ts` adds the zod payload schemas (`ExecutionRequestedPayloadSchema`, `ExecutionResultPayloadSchema`, `ReconciliationPayloadSchema`), writers that return `EntryInput`s and throw on an invalid payload (`executionRequestedEntry`, `executionResultEntry`, `reconciliationEntry`), and `readExecutionHistory(dbOrTx)` returning `{ known: true, executions }` or `{ known: false, seq, detail }`.
- Payload shapes: a request has `requestId` (must equal `intentHash`) and `replay: false, decisionSeq` or `replay: true, firstRequestSeq, proposal, proposalTruncated` (writer takes `replayOf: { firstRequestSeq, proposal }`, proposal text via `proposalText`). A result has `requestSeq`, `outcome`, `refund { id, status }`, optional `error { name, issues, debugId }`; no intent ID in the payload (it's the ref) and its time is the entry's `at`. A reconciliation has `source` (`webhook` needs `event { id, type }`), `refund { id, captureId, status, amount }`, `resultSeq` (nullable).
- Gotcha: "no later failed result" is read per intent: an intent counts unless its latest request-or-result entry is a `failed` result. So failed then replay (no result yet, or executed) counts again, fail closed. T-006: a replay past 6 hours that sends nothing should not write a replay `execution.requested` after a failed result, or the intent will block its capture again.
- Gotcha: the history is also unknown for a result naming a request of another intent or no request, a replay of no earlier request, or a ref that isn't the payload's intent ID. Pass `log.tx` from `withAuditLog` to read inside the deciding transaction.
