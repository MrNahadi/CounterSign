## T-006 (done)
- `apps/storefront/src/seed-run.ts` exports `runSeed({ paypal, db, orders, runId, vaultTokens: { A, B }, clock, databaseReason? })` returning a `SeedReport` (`runId`, `total`, `seeded`, `counts` by shipment status, `failures` as `{ orderNumber, call, reason, debugId }` sorted by order number, `problem`), plus `SAME_BUYER_PROBLEM` and `SEED_CONCURRENCY`. It throws before any call on a bad run ID ("The run ID must be ..."), a missing vault token ("The vault token for buyer B is missing.") or a bad clock value. Tests in `apps/storefront/test/seed-run.test.ts` over a stateful fake sandbox `apps/storefront/test/fake-sandbox.ts` (replays POSTs by request ID, hooks to edit or fail answers per order, counts orders in flight).
- Gotchas for T-007: `clock` is read once per run, so every row and shipment in one run shares `seededAt`. Pass `databaseReason: (e) => failureReason(e, target)` from `@countersign/db` so write failures carry a scrubbed driver message (the default is generic). Failure `reason` is the PayPalError message without the call prefix and debug ID, so the CLI line is `${orderNumber} ${call} ${reason}` plus the debug ID. Rows already seeded for the run (valid by zod and matching the catalog's buyer and tracking number) are skipped with no PayPal call; a new run upserts over an earlier run's `seed_orders` rows (ADR 0023) and adds its own shipments. Once buyers A and B clash, no new orders start and `problem` is set; the CLI should exit 1 on `problem` or any failure. The seed test file takes about 18 s (one PGlite per test).
