# 0043. The console opens on a start page with the guide, the scenario launcher and the reset; every console route to Resolve needs the approvals sign-in; on the hosted demo, baseline mode runs only the fixed demo scenarios

Status: accepted, extends ADRs 0030 (Resolve's intake), 0031 (the two modes) and 0038 (routes to Resolve behind the sign-in)
Decided-by: autopilot (delegated), phase 13 design draft, 25 Oct 2026, under brief §14 v1.4. It's a critical decision (`.ralph/egm/PROCESS.md`): it decides authentication on the public URL and changes what a judge sees and what baseline mode can move. ADR 0031 left "whether baseline mode is offered on the hosted URL" to this phase. The planner session had no way to start the answerer agent or a Goldfish sub-agent, so it applied the answerer's rules itself and wrote the strongest case against its own choice below; round A's Design Critic reviews it fresh. Decided by brief §10 trade-offs 1 (fail closed), 3 (the judge path works every time) and 4 (a stranger understands it in 60 seconds). The owner can overturn it (`.ralph/human.md`, Decided for you)
Question: On the public hosted URL, where does a judge land, how do they run the main scenarios, what can someone without the approver key do, and is baseline mode (PayPal's toolkit wired straight to the sandbox, with a dependency tree that has known vulnerabilities) offered at all?
Decision:
- **The console's `/` is the start page**, first in the sidebar as "Start here": a one-line pitch, five numbered steps that take about a minute to read, what's real and what's simulated, the scenario launcher, the "Open on your phone" code for Approvals, and the reset. The guide reads the same signed in or out; the launcher and the reset appear once the approver is signed in, and a sign-in form takes their place before that.
- **The launcher runs three fixed scenarios**, the demo path's beats, from the files Resolve already has: the attack email (beat 3, protected or baseline), the stalled parcel (beat 4, protected) and the damaged basket (beat 5, protected). The console sends only the scenario's ID and mode; Resolve reads the file, resolves its sender from `seed_orders` as the `resolve` CLI does, and stores and queues it exactly as `POST /messages` does, under the same daily cap. The console then opens the new thread in the inbox. The dispute beat stays on the Disputes page, from disputes opened ahead of judging (brief §5 cut lines); payouts stay with the ops agent CLI.
- **Every console route to Resolve needs the approvals sign-in**, checked with the gate first and never sent to Resolve (ADR 0038's pattern, in one shared helper): the inbox page, the thread, photo and message routes, the customer chat's calls, and the new scenario route. Before this, the inbox and chat routes were open, which on a public URL would let anyone start Gemini runs and baseline runs. Signed out, the inbox shows the sign-in and the chat says to sign in on the start page.
- **Baseline mode on the hosted demo runs only the fixed scenarios.** Resolve reads `RESOLVE_BASELINE`: `on` (the default, unchanged behaviour), `scenarios` (baseline only through the launcher's scenarios that allow it) or `off`. Any other value counts as `off` and is named at startup. The blueprint sets `scenarios`. So no text a visitor writes ever reaches PayPal's toolkit on the hosted demo, while a judge can still switch the attack email to baseline and watch the same agent move sandbox money (brief §5 item 6).
Basis:
- Brief §5 item 6 ("A judge can switch Resolve to baseline mode and watch the same agent wired straight to PayPal's tools"), item 8 ("open the hosted URL, follow a 60-second guide, run the main scenarios from a scenario launcher, open the approvals page on their phone through a QR code, and reset the demo"), §3 (judges: "the hosted path takes ≤ 5 minutes: hosted URL, sandbox login, scenario launcher, reset"), §5 ("Nothing is cut to save build effort"), §8 (the public demo can't run up unbounded AI cost; simulated parts are labelled; the baseline isn't tuned to fail), §12 (judge guide with an approver login; "Attack it yourself" with its own rate limit, phase 15).
- `docs/spikes.md` S4: "`npm audit` reports 11 vulnerabilities (6 high), all inside the toolkit's dependency tree … Phase 8 should keep baseline mode off the public hosted path." ADR 0031: "phase 13 decides whether baseline mode is offered on the hosted URL."
- ADR 0038 ("Any later console route to Resolve that needs the sign-in follows the same pattern. Put it in one helper"), ADR 0030 (the console reaches Resolve only from server routes), ADR 0032 (the approver key is checked by the gate only).
Goldfish argument (the Elephant's own steelman, since no fresh sub-agent could be started): "Putting the whole inbox behind the approver key adds a sign-in before a judge sees anything, against trade-off 4, and the key will be public anyway once it's in the Devpost text, so it guards nothing. Baseline limited to three canned scenarios makes the comparison look staged: a judge can't try their own attack against the unprotected agent. Either offer baseline fully, which is honest, or not at all, which is safe."
Answer: The guide itself needs no sign-in, so a judge reads the whole minute's story before typing anything; the key gates only what spends money or AI calls, which §8 requires to be bounded. The Devpost testing instructions are visible to judges rather than the public repo, and the daily run cap still holds if the key spreads. Offering baseline fully would put visitor-written text into a dependency tree with known high-severity vulnerabilities, running beside the service that holds the Gemini key; that's a fail-closed question (trade-off 1, absolute), not a presentation one. Removing baseline would cut an in-scope item, which the brief forbids. The fixed attack email is the demo's own cold open and isn't tuned to fail (§8); the integrity rule there is about the baseline's tuning, not the input's source. "Attack it yourself" (phase 15) gives visitors free text against the protected agent.
Consequences:
- The console's existing route tests change: route-level calls now carry a signed-in cookie and a gate that takes the key; the inner functions don't change.
- `npm run resolve -- --mode baseline` (the local CLI) ignores `RESOLVE_BASELINE`; it's the operator's tool and runs in-process.
- Phase 15 adds a public "Attack it yourself" path with its own per-session rate limit and spend cap, in protected mode only.
- The owner puts the approver key in the Devpost testing instructions and the judge guide points there (`.ralph/human.md`).
